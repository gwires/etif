# Milestone 1: Flake + Dev Shell

## Goal
Create a Nix flake that provides a reproducible development environment with all required tools.

## Context
This is the foundation. No code can be written or run without this. The machine is memory-constrained so the flake must be lean.

## Required Tools in Dev Shell
- `deno` — backend runtime
- `pnpm` — frontend package manager
- `nodejs` — required by SvelteKit tooling
- `dbmate` — database migration tool
- `postgresql` — database server (for local dev)
- `libpq` — PostgreSQL client library
- `s2geometry` — S2 geometry C++ library (headers + shared lib for pg_s2)

## Deliverables

### `/flake.nix`
- Inputs: nixpkgs (stable channel)
- Output: `devShells.default` with all tools above
- Use `mkShell` not `buildEnv` (lighter)
- Set env vars: `DATABASE_URL`, `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`
- Include a `shellHook` that prints available tools and versions on shell entry

### `/flake.lock`
- Generated by running `nix flake lock`

## Verification
```bash
nix develop
deno --version
pnpm --version
node --version
dbmate --version
psql --version
```

All commands must succeed inside the dev shell.

## Constraints
- Do NOT add unnecessary packages. Every package must be justified.
- Do NOT use overlays unless absolutely required.
- Prefer `nixpkgs` packages over custom builds.
- Keep eval time low — avoid heavy computations in flake.
- Memory-conscious: no parallel builds during `nix develop`.

## Notes
- If `pg_s2` or `s2geometry` is not in nixpkgs, note it as a follow-up and skip for now. We will handle it in milestone 2.
- The PostgreSQL service itself will be started manually or via process-compose later, not in the flake.
